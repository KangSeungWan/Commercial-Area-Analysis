# 사전 분석 계획 — 공사 피해를 '시가 정한 공사 영향 상권 52곳'으로 다시 재기 (2026-11-12, 결과 보기 전 작성)

## 왜
- 대전시 정보공개 답변(2026-11, 소상공정책과): 공사 차량 통제구간 45곳에서 직선 500m 안 상권 52곳(8989 골목상권 144개 기준).
- 지금 공사 분석(`analyze_construction_trdar.py`)의 처리군은 우리가 정한 '공사 구간 정거장 300m 안' 30곳 → 시 목록과 20곳만 겹침.
- 시가 직접 정한 영향권으로 같은 방법을 다시 돌려, 결론('동 평균 공사 손실 확인 안 됨')이 처리군 정의에 달려 있는지 확인.

## 방법 (기존 스크립트와 같은 것, 처리군만 바꿈)
- 자료: 8989 골목상권 월 카드매출 2024-01~2026-08(지금 있는 자료, 재수집 없음), 23업종
- 처리군: 시 목록 52곳(이름으로 8989 골목상권 코드와 맞춤, 52곳 모두 맞음). 같은 값 묶음(dup_group)은 묶음당 1곳, 축제 유형 제외
- 공사 시작 달: 시 답변의 공구 → `data/construction_sections.csv`의 공구 시작 달(1·2공구 2025-03, 7공구 2025-04~2027-08, 나머지 2026-03). 여러 공구에 걸치면 가장 이른 달
- 비교군: 기존과 같음 — 모든 트램 정거장에서 1km 넘게 떨어진 골목상권 중 시 목록에 없는 곳
- 모형: log(월 매출) ~ 골목상권 고정효과 + 월 고정효과 + 처리×공사 중, 골목상권 군집 표준오차
- 함께 보는 검사: 가짜 공사 시작(12개월 앞당김, 공사 전 자료만), 사건연구(공사 시작 −12~+17개월), 음식점·소매 따로

## 판정 규칙 (결과를 보기 전에 정함 — 결과에 맞춰 바꾸지 않음)
| 결과 | 판정 |
|---|---|
| 전체 카드매출 효과가 음수, p < 0.05, **그리고** 가짜 공사 시작이 p ≥ 0.10 | '확인 안 됨' → **'방향만'**으로 올림: "시가 정한 영향 상권에서는 공사 중 매출 감소가 통계적으로 보임". 크기는 구간으로만 말함 |
| 음수, p < 0.05, 그런데 가짜 공사 시작도 p < 0.10 | '확인 안 됨' 유지: 공사 전부터 흐름이 달랐을 수 있음(평행 추세 의심) |
| p ≥ 0.05 (부호 상관없음) | '확인 안 됨' 유지: "시가 정한 영향 상권으로 다시 재도 동 평균·상권 평균 손실은 확인 안 됨" |
| 양수이고 p < 0.05 | '확인 안 됨' 유지 + 반대 결과 칸에 적음(공사 구간이 오히려 좋았다고 해석하지 않음 — 원도심 회복 등 다른 흐름 가능) |
- 기존 결과(30곳, −1.3% [−7.6, 5.4])는 지우지 않고 나란히 보여 줌. 둘 중 유리한 쪽만 고르지 않음
- 13공구 원도심(19곳)·전통시장·상점가만 같은 하위 묶음은 **참고**로만 보고, 등급을 바꾸지 않음
- 이 검정은 검정 목록(`tests_registry.csv`)에 추가해 다중 검정 보정 대상에 넣음
- 한계: 공사 시작 달은 언론 보도 기준 공구 묶음(정보공개 2번 '공구별 공사 일정' 답 오면 교체), 8989 매출은 신한카드 보정 추정치, 2026-09 이후 자료 없음
