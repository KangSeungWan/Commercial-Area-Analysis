- 출처: https://8989.daejeon.go.kr (대전신용보증재단). 분석 화면이 쓰는 `/map/getAnalInfo.json` 을 그대로 호출. 로그인 불필요(익명 세션 쿠키만).
- **약관 주의**: 사전 승낙 없는 복제·타인 제공 금지 조항 있음 → 대회 제출·공개 전 재단(042-380-3942)에 활용 승낙 확인. 원본 `data/raw/8989/raw/` 는 Git 제외(.gitignore 추가됨).
- 단위: 행정동 82개(8989 코드 2501xxxx ↔ 행안부 30xxxxxx ↔ 통계청 `adm_cd2`; `outputs/8989/dong_code_map.csv` 에서 82개 모두 이름으로 대응 확인), 골목상권 164개(골목형상점가 102·전통시장 25·상점가 16·축제 20·활성화구역 1), 업종 대분류 8·소분류 79.
- 기간: 카드매출(`selng01`) 2025-01~2026-08, 유동인구·주민인구 2024-01~2026-08, 점포·폐업은 기준월 기준 13개월. 매월 갱신(매월 18일 새벽 무렵) → 한 달 뒤 `download_8989.py` 를 다시 돌리면 새 달만 추가하도록 기준월 목록(YM_MAIN)에 최신 달을 넣을 것.
- 실행 (Project 폴더, 가상환경):
  ```
  python tram_model/download_8989.py --meta              # 코드표·경계 (1분)
  python tram_model/download_8989.py                     # 행정동 82 × 소분류 79 × 기준월 2 ≈ 1.3만 회, 3스레드 약 2시간. 끊기면 재실행(이어받기)
  python tram_model/download_8989.py --industries core   # 핵심 27업종만 (약 40분)
  python tram_model/download_8989.py --trdar             # 골목상권도 (약 4시간 추가)

  ```

- 항목 해석 주의
  - `selng01`(월별 매출)이 소분류 업종 기준 월 시계열. `selng03~05`(요일·성별·연령)는 합계가 `selng01`과 달라(약 1.7배) 집계 기준이 다른 것으로 보임 → **비율 용도로만**.
  - `selng02`는 2024-01부터 있으나 월별로 크게 출렁임 → 온통대전(지역화폐) 결제액으로 추정. 매출로 쓰지 말 것.
  - 상권 응답의 `trdarNo` −1·−2 행은 사이트가 붙이는 비교군(`level=trdar_ref-1/-2`). 의미 미확인.
  - 어느 카드사 자료인지 미확인 → 절대 금액보다 비율·증감 위주.
  - 주민인구(`popul05`)는 `popul06` 성·연령 합과 일치. 은행선화동은 2024-01 1.39만 → 2026-07 2.42만으로 급증(재개발 입주로 보임, 확인 필요).
- 활용 계획: 82개 행정동을 기본 분석층으로 추가(상권 20개는 500m 트램 효과용으로 유지). 상권 매출은 걸치는 행정동 매출을 점포 수 비율로 배분해 합성값(`sales`) 대체. 행정동 실측 매출 증감 vs 쇠퇴·성장 점수 상관으로 외부 검증.
- 현재 상태: 표본 4건(은행선화동 음식점·주점, 유성문화원 골목형상점가)으로 정리 스크립트 동작 확인. 본수집은 맥 터미널에서 실행 필요(Claude 작업 VM은 외부 사이트 접근 불가).
